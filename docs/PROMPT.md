# ТЗ для агентов: ToF / rolling shutter на OV7670

> Это **главный промпт**. Агент, взявший проект, читает его целиком, затем
> `AGENTS.md`, `docs/theory.md`, `docs/hardware.md`, `docs/measurements.md`,
> `board/` и MCP `pinmap`. Работать итеративно, фиксировать факты в `docs/`.

## 1. Роль и цель

Ты — FPGA/HW-инженер-исследователь. Нужно **экспериментально** ответить на
вопрос: можно ли измерить дальность/глубину камерой OV7670 + импульсным светом,
и если нет — то что именно измеримо и какими методами получить глубину.

Цель — не «сделать красиво», а **добыть проверенные числа**: тайминг камеры,
время строки `T_row`, поведение полосы света при свипе задержки, границы
метода. Всё подтверждается симуляцией и/или измерением на железе.

## 2. Что уже известно (не переоткрывать)

Из `004_rolling_shutter` (см. `docs/theory.md`, `docs/measurements.md`):

* Direct ToF недостижим: `δd ≈ c·T_row/2 ≈ 9.8 км` (при `T_row ≈ 65 мкс`).
* AMCW/iToF недостижим: `T_exp ≥ T_row`, контраст `sinc(π·f_mod·T_exp) → 0`.
* QQVGA (измерено): кадр ≈ 64 мс, 120 строк, 160 px, `T_row ≈ 533 мкс`.
* TFT: 16 бит RGB565, `MADCTL=0x08` (BGR), окно + `RAMWR`; write-only.
* Камера: RGB565 (полная таблица, AGC/AEC ON) для картинки; YUV (AGC/AEC OFF)
  для измерений с фиксированной экспозицией.

## 3. Аппаратный стенд

| Узел | Как подключить | Примечание |
|------|----------------|------------|
| ПЛИС | OMDAZZ Cyclone IV, USB-Blaster (JTAG) | `quartus_pgm -c USB-Blaster -m JTAG` |
| Камера | OV7670 на GPIO-гребёнку (раскладка 001/002) | XCLK 87, VSYNC 88, HREF 89, PCLK 90, D[7:0] 98..106, SCCB 84/85 |
| Дисплей | TFT 240×320 на GPIO (распайка `docs/hardware.md`) | RS 3, WR 1, RD 143, CS 114, RESET 113, DB[15:0] |
| Строб | **внешняя неадресная LED-лента** через MOSFET | затвор → свободный GPIO (напр. 43/55/58/60/110); питание отдельное |
| UART | CH342 → `/dev/ttyACM1`, 115200 8N1 | TX FPGA на PIN_42 |

**Неадресную** ленту (белую/аналоговую RGB) — можно. **WS2812** — нельзя
(медленный протокол, ШИМ ~1 кГц). GPIO напрямую ленту не питает — только
через MOSFET.

## 4. Задачи (по этапам)

### Этап 0 — стенд (L0)
- [ ] Сверить пины по `board/` и MCP `pinmap`; зафиксировать в `docs/hardware.md`.
- [ ] Убедиться, что камера и дисплей одновременно помещаются (нет конфликта).
- [ ] `docs/decisions/` — ADR о выборе пина строба и типа ленты.

### Этап 1 — видеотракт (L0–L3, L4–L5, L6)
- [ ] RTL: XCLK, SCCB-инициализация OV7670, DVP-захват, кадровый буфер,
      вывод на TFT (16 бит RGB565, `MADCTL=0x08`).
- [ ] Testbench: камера-модель + TFT-модель; проверить кадр.
- [ ] Синтез/тайминг Quartus; прошить; **на экране — картинка с камеры**.
- [ ] Зафиксировать в `docs/measurements.md`.

### Этап 2 — экспозиция + строб
- [ ] Короткая экспозиция (рег. `AECH`/`AECL`), усиление; подобрать по дампу.
- [ ] Строб на LED-ленте: короткий импульс ~`T_row`, синхронный началу кадра,
      задержка **свипуется** от кадра к кадру.
- [ ] Дамп профиля яркости по строкам через UART (формат `F`/`R`).
- [ ] Добиться, чтобы **полоса света была видна** и двигалась при свипе.

### Этап 3 — измерение
- [ ] Измерить `T_row`: `Δrow = Δdelay / T_row` (сравнить с `cycles/lines`).
- [ ] Оценить ширину/контраст полосы; проверить предсказание `docs/theory.md`.
- [ ] Оформить таблицу измерений и график (по возможности).

### Этап 4 — ToF-осуществимость и альтернативы
- [ ] Экспериментально подтвердить/опровергнуть недостижимость ToF
      (контраст модуляции vs `f_mod`).
- [ ] Оценить **структурированный свет** (TFT как проектор) и
      **лазерную триангуляцию** — что реально даёт глубину на этом сетапе.

### Этап 5 — документация
- [ ] `docs/measurements.md`, `docs/results.md` — числа и выводы.
- [ ] Обновить `AGENTS.md`/`README.md` статусом.

## 5. Ограничения и правила

1. Не выдумывать пины/регистры/тайминги — только datasheet, симуляция, измерение.
2. HDL читаемо, явные clock/reset, `always_ff`, testbench к каждому модулю.
3. Итерация «прошил → снял UART → разобрал». Не «на глаз».
4. Всё проверенное — в `docs/`; ADR — для решений.
5. **Секреты не коммитить** (токены/пароли/`.env`/ключи). MCP-конфиг без кредов.
6. Люмен/яркость не выдумывать — измерять по `Y` (8 бит).

## 6. Критерии готовности

* На TFT стабильно виден кадр с камеры (16 бит, правильные цвета).
* Полоса от строба видна и **смещается на 1 строку при +1 `T_row` задержки**.
* `T_row` измерен и согласуется с `cycles/lines` (в пределах дискретности).
* Есть вывод (с числами) о (не)осуществимости ToF и о реалистичных альтернативах.

## 7. Что НЕ делать

* Не переносить сюда весь `Altera_FPGA_OMDAZZ` — только нужное.
* Не использовать WS2812 как строб.
* Не питать LED-ленту от GPIO напрямую.
* Не «подгонять» числа под теорию — измерять.
* Не коммитить секреты.
